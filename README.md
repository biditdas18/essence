# Essence: Peer-Isolated Recommendation

**Domain-dependence and clustering-mechanism results, with validated $K$ (2026 update):** the original framing of this project ("Essence recovers long-tail content better than collaborative filtering, full stop") does not hold up under a broader evaluation. Across three datasets and ten baseline systems, Essence's relative performance is **domain-dependent**: it ranks 2nd of 10 on Last.fm-1K and 3rd of 10 on Amazon Books, where collaborative/popularity signal is structurally weak, but 8th of 10 on MovieLens-25M, where collaborative signal is strong. A targeted stratification test further shows that **the $K$-means clustering step itself, isolated from recency-weighted retrieval, is not empirically supported as the source of Essence's advantage** where an advantage exists: no stratum, on any dataset or metric, shows Essence significantly ahead of Recency-Weighted retrieval alone. $K$ (the number of interest clusters) is now **validated per dataset** on a held-out validation split rather than fixed at an arbitrary $K{=}3$ — this changed several numbers substantially (see [Key Findings](#key-findings)) without changing the domain-dependence conclusion. This README documents the full, current picture — the wins, the losses, and the null result — not the original favorable framing, and not the earlier fixed-$K{=}3$ numbers.

## What Essence Is

Essence is a personal recommendation framework that operates exclusively within a single user's own engagement history, without consulting cross-user interaction data ("peer isolation"). A user's consumed items are embedded with a pre-trained sentence encoder (`all-MiniLM-L6-v2`), clustered into $K$ semantic centroids via $K$-means, and recommendations are generated by retrieving unseen items similar (cosine similarity) to whichever centroid is closest to the user's most recent activity.

**This repository is structured as an evaluation study, not a method-introduction project**: the central question is whether $K$-means interest clustering, specifically, provides measurable benefit over a simpler recency-based alternative, tested under conditions designed to give clustering its best chance to matter. The central empirical question is not "does Essence work" but **"under what domain conditions does peer-isolated, content-only personalization help versus hurt, and is that association predictive?"** (it is not yet shown to be — see [Key Findings](#key-findings)) — see [Headline Results](#headline-results-all-three-datasets) below.

## $K$-Selection Methodology

$K$ is selected per dataset on a validation split carved from training data (the last 20% of each user's chronological training history; the held-out test set is never touched during selection). $K$ is swept over $\{2, 3, 4, 5, 8, 10, 15, 20, 30, 50\}$ (log-spaced above 8), stopping at the first $K$ where either (a) validation Recall@10 improves by less than 2% relative to the previous tested $K$, or (b) mean items-per-cluster falls below 3 — whichever fires first. The selected $K$ is the validation-Recall@10-maximizing point before the stopping rule triggers. This yields:

| Dataset | Selected $K$ | Stopping condition |
|---|---|---|
| Last.fm-1K | 10 | (a) — K=15 showed a −3.3% regression |
| Amazon Books | 10 | (b) — mean items/cluster fell to 2.58 at K=10 |
| MovieLens-25M | 15 | (a) — K=20 showed <2% improvement (and would also have triggered (b) shortly after) |

**Disclosed scope decision**: the sweep proceeded forward from an already-established $K{=}8$ checkpoint rather than restarting from $K{=}2$. Applied retroactively to the $K \in \{2,\ldots,5\}$ region, the rule would in fact have fired earlier for Amazon Books and MovieLens-25M, since validation Recall@10 dips slightly across some closely-spaced early $K$ values before climbing again. This is disclosed as a scope decision, not a result the stopping rule itself produced from a clean start. Full sweep data: `results/validation_k_sweep_{lastfm,amazon,movielens}.csv`.

## Datasets

| Dataset | Domain | Users | Catalog items | Raw/processed data |
|---|---|---|---|---|
| **Last.fm-1K** | Music | 99 (the full filtered dataset, not a subsample) | 22,767 | `data/raw/` (not committed, downloaded by script) → `data/` processed CSVs |
| **Amazon Books** | E-commerce | 2,000 (subsampled) | 61,727 | `data/amazon_raw/` (not committed) → `data/amazon_processed/` |
| **MovieLens-25M** | Film | 2,000 (subsampled) | 7,654 (with fetched TMDb overview text) | `data/movielens_raw/` (not committed) → `data/movielens_processed/` |

All three use a **chronological 80/20 split per user** (first 80% of a user's interactions by timestamp = train, last 20% = test), computed independently per user with no shared global time cutoff — required for consistency with Essence's recency-based active-cluster-selection mechanism, which defines "recent" in terms of training-set order. **This does not prevent cross-user temporal leakage** for population-based baselines (CF, Popularity): an item's co-occurrence signal can include other users' interactions that occurred, in wall-clock time, after a given user's personal train/test cutoff. This is a disclosed limitation of the evaluation protocol, not eliminated by the per-user split.

A positive interaction is any recorded play (Last.fm-1K), rating or review (Amazon Books), or rating (MovieLens-25M) — no minimum count or rating-value threshold beyond the per-user interaction-count filters (50–500 Last.fm-1K, 20–200 Amazon/MovieLens). This evaluates engagement/consumption prediction, not preference prediction specifically; a positive-rating threshold (e.g., rating ≥ 4) was not tested.

Long-tail items are defined per dataset as training-set singletons (interaction count exactly 1): 16,761/18,679 (89.7%) on Last.fm-1K, 42,878/50,924 (84.2%) on Amazon Books, 2,337/6,745 (34.6%) on MovieLens-25M. LT-Recall@10 eligible users (at least one long-tail test item): 92 of 99 on Last.fm-1K, 1,292 of 2,000 on Amazon Books, 490 of 2,000 on MovieLens-25M.

## Systems Compared

| System | Query construction |
|---|---|
| Random | Uniform random over unseen items |
| Popularity | Most globally-interacted-with unseen items (non-personalized) |
| CF (ItemKNN) | Item-based cosine-weighted aggregate over the user-item co-occurrence matrix; no neighbor-count cutoff or shrinkage (full-neighborhood, $k=\infty$) |
| Content (Avg Emb) | Cosine similarity to the mean of all history embeddings |
| **Essence (validation-selected $K$)** | Cosine similarity to the active $K$-means centroid ($K{=}10$ Last.fm-1K/Amazon Books, $K{=}15$ MovieLens-25M) |
| Last-Item | Cosine similarity to the single most recent item |
| Avg-Last-10 | Cosine similarity to the uniform mean of the last 10 items |
| Recency-Weighted | Cosine similarity to an exponentially-decayed mean (decay $=0.9$) of the last 10 items |
| MIND | Dynamic-routing multi-interest capsules ($K{=}4$), hand-implemented — not available in standard recommendation libraries |
| ComiRec (SA) | Self-attentive multi-interest capsules ($K{=}4$), hand-implemented |

Last-Item, Avg-Last-10, and Recency-Weighted use the *identical* item embeddings as Content and Essence — the only difference across those five systems is how the query vector is built from recent history. This isolates whether Essence's clustering step adds anything beyond simple recency weighting (see [Key Findings](#key-findings)).

MIND and ComiRec are verified against their architectural specifications rather than against the original papers' published benchmark numbers, since neither paper's evaluation protocol (sampled-negative, different datasets) matches this repo's full-catalog, no-negative-sampling, chronological-split protocol; both are hand-implemented since neither is available in standard recommendation libraries (RecBole was checked directly and confirmed not to ship either). Both are trained with Adam (lr $=10^{-3}$), batch size 64, up to 50 epochs with early stopping (patience 5) on held-out-last-interaction validation loss, and a sampled-softmax loss (100 uniform-random negatives per positive). See [MIND/ComiRec training and verification](#mindcomirec-training-and-verification) below for how correctness is checked.

## Headline Results, All Three Datasets

Full per-dataset headline tables (Recall@10, LT-Recall@10, domain-dependence table, cold-start decile breakdown, and the multimodality-stratification test) are in the paper (`paper/essence_paper_v2.tex`, Section 5). Summary at each dataset's validation-selected $K$:

| Dataset | Essence Recall@10 (rank of 10) | Essence LT-Recall@10 (rank of 10) | CF/Popularity signal strength |
|---|---|---|---|
| Last.fm-1K ($K{=}10$) | 0.0281 (**2nd**) | 0.0142 (**2nd**) | Weak (CF 0.0018, Popularity 0.0023) |
| Amazon Books ($K{=}10$) | 0.0253 (**3rd**) | 0.0207 (**2nd**) | Weak (CF 0.0031, Popularity 0.0021) |
| MovieLens-25M ($K{=}15$) | 0.0053 (**8th**) | 0.0030 (**4th**) | **Strong** (CF/Popularity/ComiRec/MIND are the top 4 systems) |

Compare to the earlier fixed-$K{=}3$ ranks: Last.fm-1K 5th→**2nd**, Amazon Books 4th→**3rd**, MovieLens-25M unchanged at 8th. Essence's own Recall@10 rose substantially on the two weak-signal datasets ($0.0119\to0.0281$ Last.fm-1K, $0.0221\to0.0253$ Amazon Books) once $K$ was properly validated instead of fixed at an arbitrary value.

Essence's rank is **associated with** collaborative/popularity signal strength in the domain across the three datasets tested — this pattern, not a fixed "Essence wins" or "Essence loses," is the empirical finding. Establishing this association as *predictive* would require additional datasets and an independently-defined domain property, not one measured post hoc via baseline performance, as here.

## Key Findings

1. **Domain-dependence, not universal advantage.** See table above. On Amazon Books, Essence significantly beats CF-ItemKNN, the non-personalized baselines, Content, and both neural baselines on Recall@10 (paired bootstrap, $d$ 0.099–0.282); it is statistically tied with (not significantly behind) Recency-Weighted and Avg-Last-10, and loses significantly only to Last-Item ($d{=}{-}0.058$). On Last.fm-1K, Essence significantly beats the same set of baselines ($d$ 0.220–0.301) and is not significantly different from *any* of the three recency-only baselines, including Recency-Weighted. On MovieLens-25M, Essence loses to CF, Popularity, and both neural baselines by the four largest effect sizes observed anywhere in this evaluation ($d$ from $-0.378$ to $-0.550$).
2. **The clustering-mechanism null result — and how much weaker the "actively hurts" evidence became.** A stratification test (`evaluation/clustering_value_test.py`) splits users by how well-separated their own clustering is (silhouette score, tertiles, computed at each dataset's validated $K$) and compares Essence against Recency-Weighted *within each stratum*. **No stratum, on any dataset or metric, shows Essence significantly ahead of Recency-Weighted** — this headline null result is unchanged from the earlier fixed-$K{=}3$ version. As a secondary detail: of the stratum/metric comparisons pooled with the baseline significance family, **6 of 17 were significant losses for Essence at $K{=}3$** (including the high-silhouette stratum on both Last.fm-1K and MovieLens-25M); at the validated $K$, **only 1 of 16 remains significant** (MovieLens-25M's high-silhouette stratum, LT-Recall@10). The evidence that clustering *actively hurts* specific identifiable user groups is now much thinner than the earlier analysis suggested — the null result itself is unaffected.
3. **A real statistical bug caught and corrected: degenerate zero-variance FDR cells.** One (at $K{=}3$) or two (at the validated $K$) stratum/metric cells in the silhouette-stratification test have every user scoring exactly 0 on *both* Essence and Recency-Weighted, giving zero variance in the paired bootstrap difference. The standard two-sided $p$-value formula is undefined in this case and, applied naively, returns $p{=}0$ ("infinitely significant") — a spurious artifact, not evidence of a real difference. These cells are now excluded from the pooled significance family rather than counted as evidence, changing the family size from a nominal 54 to 52–53 in practice. This correction applies retroactively: the original K=3 analysis had counted the degenerate cell as significant.
4. **Cold-start vs. singleton long-tail is a scope boundary, not a contradiction.** Essence beats CF-ItemKNN at true cold-start (zero training interactions) on all three datasets at the validated $K$ — unchanged from $K{=}3$, and now unambiguous rather than marginal on MovieLens-25M. But this is not evidence for Essence's architecture specifically: re-running the identical test with Recency-Weighted, Last-Item, or Avg-Last-10 in Essence's place, 15 of 18 comparisons are also significant (this check doesn't depend on Essence's $K$). The mechanism is mechanical: CF's co-occurrence score is exactly 0 for zero-interaction items by construction, so any content-embedding method clears that bar trivially. Separately, Essence's earlier ($K{=}3$) significant losses to Last-Item and Recency-Weighted at the two rarest deciles on Amazon Books are **no longer significant** at the validated $K{=}10$.
5. **The active-cluster-selection ablation, now on all three datasets.** Recency-based active-cluster selection (vs. a static full-history mean-embedding query) is retained as Essence's default mechanism: on Last.fm-1K, mean-select collapses below even the Content baseline on long-tail recall ($4.84\times$ LT/Content in recency-select's favor at the validated $K$, up from $2.01\times$ at $K{=}3$); on Amazon Books (now tested for the first time), the same pattern holds but less extremely. On MovieLens-25M, the result is genuinely mixed — recency-select leads on Recall@10 but mean-select leads on LT-Recall@10 — reported as-is, not smoothed over.
6. **The artist/author shortcut (not yet re-verified at the validated $K$).** At $K{=}3$, roughly a fifth of Essence's recommendations shared an artist (Last.fm-1K, 20.6%) or author (Amazon Books, 19.8%) with an item in the active cluster; excluding those candidates collapsed Recall@10 sharply (0.0119→0.0014 Last.fm-1K, 0.0221→0.0073 Amazon Books). This analysis has not been re-run at the validated $K$; the $K{=}3$ figures are reported as the most recent verified numbers rather than assumed unchanged.
7. **A caught implementation bug in MIND, not an architecture flaw.** An early version of the hand-implemented MIND baseline zero-initialized its routing logits, which — because MIND's bilinear routing matrix is shared across capsules — silently collapsed the model's effective interest count to 1 regardless of the nominal $K$. A synthetic conformance test caught this before any number in this repo was generated; see [MIND/ComiRec training and verification](#mindcomirec-training-and-verification).
8. **Multi-seed MIND/ComiRec robustness, re-checked at the validated $K$.** At $K{=}3$, ComiRec (SA) beat Essence on 2 of 4 Last.fm-1K training seeds — characterized as a statistical tie. At Essence's validated $K{=}10$, Essence's own Recall@10 rises enough ($0.0119\to0.0281$) that ComiRec no longer beats it on any seed (0/4). MIND never outranks Essence on Last.fm-1K/Amazon Books and always outranks it on MovieLens-25M (3/3), across every seed tested at either $K$.
9. **A second, independent collaborative baseline (BPR-MF) replicates the domain-dependence pattern exactly.** CF-ItemKNN is the only collaborative-filtering baseline behind the domain-dependence finding above; to check this isn't an artifact of that one implementation, BPR-MF (Bayesian Personalized Ranking Matrix Factorization — a pairwise-ranking method sharing no code or architecture with ItemKNN) was implemented and conformance-tested on synthetic data before trusting any real-dataset number (the conformance test itself needed one correction — an overly strict pass/fail threshold — before all checks passed; see [MIND/ComiRec training and verification](#mindcomirec-training-and-verification) for the same discipline applied to the original neural baselines). Essence significantly beats BPR-MF where collaborative signal is weak (Last.fm-1K, $d{=}{+}0.296$; Amazon Books, $d{=}{+}0.261$) and significantly loses to it where collaborative signal is strong (MovieLens-25M, $d{=}{-}0.518$, BPR-MF ranking immediately behind CF-ItemKNN and ComiRec). BPR-MF's own LT-Recall@10 is $0.0000$ on all three datasets, including MovieLens-25M where it wins decisively on Recall@10. Full numbers: `results/scratch_bprmf_{lastfm,amazon,movielens}.csv` and `results/scratch_bprmf_bootstrap_{lastfm,amazon,movielens}.csv`.

## Reproducing the Results

All results are deterministic (fixed seeds, stable tie-breaking on ties). Re-running any evaluation script reproduces the exact numbers cited.

### Install dependencies

```bash
pip install -r requirements.txt
```

The non-neural pipeline (baselines, bootstrap/FDR/BCa, decile analysis, $K$-validation sweeps) uses `requirements.txt` as pinned. **MIND/ComiRec training additionally requires PyTorch**, which is not needed anywhere else in the pipeline — see the note at the bottom of `requirements.txt` and [Dependencies](#dependencies) below.

### 7. Multimodality-stratification test (the clustering-mechanism null result)

```bash
python evaluation/clustering_value_test.py
```

## Known Limitations

These match what the paper itself states — see `paper/essence_paper_v2.tex`, Sections 5.6/6/7, for the full statements this summarizes:

- **Scale.** Last.fm-1K uses 99 users; its long-tail comparisons are directional (as few as 2 of 92 eligible users per method). Amazon Books and MovieLens-25M (2,000 users each) carry the statistical weight. A global-timestamp-cutoff split (tested as a robustness check, not adopted) strands 39% of Last.fm-1K's users (60/99 remain with data on both sides) and is uninformative at this scale — under it, Essence's Last.fm-1K standing genuinely reverses (significant losses to Recency-Weighted and Avg-Last-10, both currently reported as ties, and LT-Recall@10 collapses to 0.0000). Amazon Books, run identically, held up close to its reported findings; MovieLens-25M strands 98.6% of users (28/2,000 remain) and is too underpowered to be informative either way. This is reported as a real, disclosed sensitivity of the per-user-split protocol at Last.fm-1K's scale specifically — the per-user-split results remain what this repository reports as findings.
- **Cross-user temporal leakage.** The chronological split is computed independently per user, with no shared global time cutoff. This preserves within-user chronology but does not enforce a global temporal cutoff; possible cross-user temporal leakage for population-based baselines (CF, Popularity) is a limitation of this evaluation protocol, not eliminated by it.
- **$K$-selection anchoring.** $K$ is validation-selected per dataset, replacing an earlier fixed $K{=}3$. The one real caveat on the procedure itself: the stopping rule was applied moving forward from an already-established $K{=}8$ checkpoint, not from $K{=}2$; applied retroactively to $K \in \{2,\ldots,5\}$, it would have fired earlier for Amazon Books/MovieLens-25M.
- **Rating threshold.** All Amazon and MovieLens ratings/reviews are treated as positive interactions regardless of rating value; this evaluates engagement/consumption prediction rather than preference prediction specifically. A sensitivity analysis using a positive-rating threshold (rating ≥ 4, verified against each dataset's actual scale — Amazon is 1–5 integer stars, MovieLens-25M is 0.5–5.0 half-stars) was performed as a robustness check; it did not reverse the domain-dependence or clustering-null-result findings, though sample sizes drop 20–28% once users below the stricter floor are excluded.
- **MIND/ComiRec are hand-implemented, not pre-trained.** Both are trained from scratch per dataset rather than via production-tuned checkpoints; a well-tuned, larger-scale deployment could plausibly outperform the versions evaluated here, particularly on MovieLens-25M, where both already outrank Essence substantially.
- **The domain-dependence mechanism is not fully explained.** "Collaborative/popularity signal strength" is measured post hoc via the baselines' own performance in each domain, not from an independent domain property decided in advance; this association has not been shown to be predictive.
- **Additional robustness checks.** Multi-seed resampling (Amazon Books, MovieLens-25M) and validation-based ItemKNN hyperparameter tuning (neighbor count, shrinkage; test data never touched during the search) were each tested; neither reversed any reported finding's direction. CF-ItemKNN's Recall@10 on Amazon Books roughly doubles under validation-tuned shrinkage, but Essence still leads it by roughly $4\times$; on MovieLens-25M, tuning selected the existing untuned configuration as optimal (0% change). See [Reproducing the Results](#11-overnight-robustness-check-batch-rating-threshold-multi-seed-itemknn-tuning-global-cutoff-bpr-mf) for exact commands.
- **The artist/author shortcut analysis has not been re-verified at the validated $K$** — the $K{=}3$ figures (~20% of hits same-artist/author) are reported as the most recent verified numbers, not assumed unchanged.
- **The adaptive-weighting pilot is unvalidated** — see [above](#10-adaptive-weighting-pilot--exploratory-not-a-result).
