# Essence: Peer-Isolated Recommendation

**Domain-dependence and clustering-mechanism results (2026 update):** the original framing of this project ("Essence recovers long-tail content better than collaborative filtering, full stop") does not hold up under a broader evaluation. Across three datasets and ten baseline systems, Essence's relative performance is **domain-dependent**: it beats collaborative filtering and popularity-based baselines where their signal is structurally weak (Amazon Books, Last.fm-1K), but loses to those same baselines — and to two neural multi-interest models — where collaborative signal is strong (MovieLens-25M). A targeted stratification test further shows that **the $K$-means clustering step itself, isolated from recency-weighted retrieval, is not empirically supported as the source of Essence's advantage** where an advantage exists: the users clustering should help most (those with the most well-separated, multi-modal interest histories) show no benefit from it. This README documents that full picture — the wins, the losses, and the null result — not just the original favorable framing.

## What Essence Is

Essence is a personal recommendation framework that operates exclusively within a single user's own engagement history, without consulting cross-user interaction data ("peer isolation"). A user's consumed items are embedded with a pre-trained sentence encoder (`all-MiniLM-L6-v2`), clustered into $K{=}3$ semantic centroids via $K$-means, and recommendations are generated by retrieving unseen items similar (cosine similarity) to whichever centroid is closest to the user's most recent activity.

The central empirical question this repo answers is not "does Essence work" but **"under what domain conditions does peer-isolated, content-only personalization help versus hurt, and is that predictable in advance?"** — see [Headline Results](#headline-results-all-three-datasets) and [Key Findings](#key-findings) below.

## Datasets

| Dataset | Domain | Users | Catalog items | Raw/processed data |
|---|---|---|---|---|
| **Last.fm-1K** | Music | 99 | 22,767 | `data/raw/` (not committed, downloaded by script) → `data/` processed CSVs |
| **Amazon Books** | E-commerce | 2,000 (subsampled) | 61,727 | `data/amazon_raw/` (not committed) → `data/amazon_processed/` |
| **MovieLens-25M** | Film | 2,000 (subsampled) | 7,654 (with fetched TMDb overview text) | `data/movielens_raw/` (not committed) → `data/movielens_processed/` |

All three use a **chronological 80/20 split per user** (first 80% of a user's interactions by timestamp = train, last 20% = test) — required for consistency with Essence's recency-based active-cluster-selection mechanism, which defines "recent" in terms of training-set order. Long-tail items are defined per dataset as training-set singletons (interaction count exactly 1): 16,761/18,679 (89.7%) on Last.fm-1K, 42,878/50,924 (84.2%) on Amazon Books, 2,337/6,745 (34.6%) on MovieLens-25M.

## Systems Compared

| System | Query construction |
|---|---|
| Random | Uniform random over unseen items |
| Popularity | Most globally-interacted-with unseen items (non-personalized) |
| CF (ItemKNN) | Item-based $k$-NN over the user-item co-occurrence matrix |
| Content (Avg Emb) | Cosine similarity to the mean of all history embeddings |
| **Essence ($K{=}3$)** | Cosine similarity to the active $K$-means centroid |
| Last-Item | Cosine similarity to the single most recent item |
| Avg-Last-10 | Cosine similarity to the uniform mean of the last 10 items |
| Recency-Weighted | Cosine similarity to an exponentially-decayed mean (decay $=0.9$) of the last 10 items |
| MIND | Dynamic-routing multi-interest capsules ($K{=}4$), hand-implemented — not available in standard recommendation libraries |
| ComiRec (SA) | Self-attentive multi-interest capsules ($K{=}4$), hand-implemented |

Last-Item, Avg-Last-10, and Recency-Weighted use the *identical* item embeddings as Content and Essence — the only difference across those five systems is how the query vector is built from recent history. This isolates whether Essence's clustering step adds anything beyond simple recency weighting (see [Key Findings](#key-findings)).

MIND and ComiRec are verified against their architectural specifications rather than against the original papers' published benchmark numbers, since neither paper's evaluation protocol (sampled-negative, different datasets) matches this repo's full-catalog, no-negative-sampling, chronological-split protocol. See [MIND/ComiRec training and verification](#mindcomirec-training-and-verification) below for how this is checked.

## Headline Results, All Three Datasets

Full per-dataset headline tables (Recall@10, LT-Recall@10, domain-dependence table, cold-start decile breakdown, and the multimodality-stratification test) are in [`results/MASTER_FINDINGS.md`](results/MASTER_FINDINGS.md) and in the paper (`paper/essence_paper_v2.tex`, Section 5). Summary:

| Dataset | Essence Recall@10 rank (of 10) | CF/Popularity signal strength |
|---|---|---|
| Amazon Books | 4th (beats 6, loses to all 3 recency baselines) | Weak (CF 0.0031, Popularity 0.0021) |
| Last.fm-1K | 5th (beats 5, loses to 3 recency baselines + tied w/ ComiRec) | Weak (CF 0.0018, Popularity 0.0023) |
| MovieLens-25M | 8th (beats only Content, Random) | **Strong** (CF/Popularity/ComiRec/MIND are the top 4 systems) |

Essence's rank tracks inversely with collaborative/popularity signal strength in the domain — this pattern, not a fixed "Essence wins" or "Essence loses," is the actual empirical finding.

## Key Findings

1. **Domain-dependence, not universal advantage.** See table above. On Amazon Books, Essence significantly beats CF, Popularity, Content, and both neural baselines on Recall@10 (paired bootstrap, $d$ 0.069–0.259) but loses significantly to Last-Item and Recency-Weighted ($d{=}{-}0.090$, $d{=}{-}0.059$). On MovieLens-25M, Essence loses to CF, Popularity, and both neural baselines by the four largest effect sizes observed anywhere in this evaluation ($d$ from $-0.388$ to $-0.558$).
2. **The clustering-mechanism null result.** A stratification test (`evaluation/clustering_value_test.py`) splits users by how well-separated their own $K{=}3$ clustering is (silhouette score, tertiles) and compares Essence against Recency-Weighted *within each stratum* — the hypothesis being that clustering should help most for genuinely multi-modal users. It doesn't: in every stratum with a significant difference, Essence *loses* to Recency-Weighted, including the highest-silhouette (most multi-modal) stratum on both Last.fm-1K ($d{=}{-}0.315$) and MovieLens-25M ($d{=}{-}0.096$). No stratum, on any dataset or metric, shows Essence significantly ahead.
3. **Cold-start vs. singleton long-tail is a scope boundary, not a contradiction.** Essence beats CF-ItemKNN at true cold-start (zero training interactions) on all three datasets — but so do all three recency-only baselines (15 of 18 comparisons significant when re-run with them in Essence's place). The mechanism is mechanical: CF's co-occurrence score is exactly 0 for zero-interaction items, so any content-embedding method clears that bar trivially. This is not evidence for Essence's architecture specifically.
4. **The artist/author shortcut.** ~20% of Essence's recommendations share an artist (Last.fm-1K) or author (Amazon Books) with an item in the active cluster; excluding those candidates collapses Recall@10 sharply (0.0119→0.0014 Last.fm-1K, 0.0221→0.0073 Amazon Books). A disproportionate share of hits are closer to identity-based retrieval than genuinely novel content matches.
5. **A caught implementation bug, not an architecture flaw.** An early version of the hand-implemented MIND baseline zero-initialized its routing logits, which — because MIND's bilinear routing matrix is shared across capsules — silently collapsed the model's effective interest count to 1 regardless of the nominal $K$. A synthetic conformance test caught this before any number in this repo was generated; see [MIND/ComiRec training and verification](#mindcomirec-training-and-verification).

## Reproducing the Results

All results are deterministic (fixed seeds, stable tie-breaking on ties). Re-running any evaluation script reproduces the exact numbers cited.

### Install dependencies

```bash
pip install -r requirements.txt
```

The non-neural pipeline (baselines, bootstrap/FDR/BCa, decile analysis) uses `requirements.txt` as pinned. **MIND/ComiRec training additionally requires PyTorch**, which is not needed anywhere else in the pipeline — see the note at the bottom of `requirements.txt` and [Dependencies](#dependencies) below.

### 1. Per-dataset baseline evaluation (headline Recall@10 / LT-Recall@10 tables)

```bash
# Last.fm-1K
python data/preprocess.py                       # download + chronological split
python embeddings/generate_embeddings.py        # -> embeddings/item_embeddings.pkl (not committed)
python evaluation/evaluate.py                   # all 8 non-neural systems -> stdout + CSV

# Amazon Books
python experiments/amazon_books/step0_download.py
python experiments/amazon_books/preprocess_amazon.py
python experiments/amazon_books/generate_embeddings_amazon.py
python experiments/amazon_books/evaluate_amazon_peruser.py    # -> results_amazon_peruser.csv

# MovieLens-25M (order matters: each step consumes the previous step's output)
python experiments/movielens/preprocess_movielens_step1.py    # -> item_candidates.csv
python experiments/movielens/fetch_tmdb_overviews.py           # -> tmdb_overviews.jsonl; requires TMDB_API_KEY in .env
python experiments/movielens/build_item_text.py                # -> item_text.csv (combines candidates + fetched overviews)
python experiments/movielens/preprocess_movielens_step2.py     # -> train.csv, test.csv, longtail_items.csv (chronological split)
python experiments/movielens/generate_embeddings_movielens.py  # reads item_text.csv
python experiments/movielens/evaluate_movielens.py             # -> results_movielens_aggregate.csv, results_movielens_peruser.csv
```

Each of the three commands above evaluates the 8 non-neural systems only (Random, Popularity, CF, Content, Essence, Last-Item, Avg-Last-10, Recency-Weighted). MIND and ComiRec are trained and evaluated separately (below); the canonical 10-system per-user files cited in `MASTER_FINDINGS.md` (`evaluation_results_v7_mind_comirec.csv`, `results_amazon_peruser_mind_comirec.csv`, `results_movielens_peruser_full.csv`) are produced by concatenating the 8-system output above with the MIND/ComiRec per-user output from the training step. **This merge step exists only as an ad-hoc pandas operation from earlier in the project, not as a checked-in script** — the exact merge is a two-line `pd.concat` of the two per-user CSVs on matching `user_id`/`system`/`recall@10`/`long_tail_recall@10` columns. This is a known reproducibility gap; a proper merge script is a good first improvement for anyone picking this repo back up.

### 2. MIND/ComiRec training and verification

```bash
# Conformance test — verifies MIND's routing mechanism actually differentiates capsules
# (this is what caught the routing-collapse bug; run this before trusting any MIND number)
python experiments/mind_comirec/test_mind_routing.py

# Canonical training run (one dataset, one model at a time)
python experiments/mind_comirec/train.py --dataset lastfm --model mind
python experiments/mind_comirec/train.py --dataset amazon --model mind
python experiments/mind_comirec/train.py --dataset movielens --model mind

python experiments/mind_comirec/train.py --dataset amazon --model comirec

# Directional/order-of-magnitude sanity check (both models, both datasets it was run on)
python experiments/mind_comirec/sanity_check.py
```

`train.py` accepts `--dataset {lastfm,amazon,movielens}`, `--model {mind,comirec}`, `--epochs`, `--embed-init {pretrained,random}`, `--lr`, `--seed`, `--K`, and `--tag` (appended to output filenames for sweep runs). See `experiments/mind_comirec/sanity_check.py`'s docstring for why a benchmark-number match against the original papers isn't meaningful here (different datasets, sampled-negative vs. full-catalog protocol).

## Known Limitations

These match what the paper itself states — see `paper/essence_paper_v2.tex`, Sections 5.6/7, for the full statements this summarizes:

- **Scale.** Last.fm-1K uses 99 users; its long-tail comparisons are directional (as few as 2 of 92 eligible users per method). Amazon Books and MovieLens-25M (2,000 users each) carry the statistical weight.
- **$K$ sensitivity untested on MovieLens-25M.** $K{=}3$ is suboptimal on Last.fm-1K, near-optimal on Amazon Books; the sweep has not been run on MovieLens-25M, so whether $K{=}3$'s weak MovieLens performance is partly a $K$-choice artifact rather than purely a domain effect remains untested.
- **MIND/ComiRec are hand-implemented, not pre-trained.** Both are trained from scratch per dataset rather than via production-tuned checkpoints; a well-tuned, larger-scale deployment could plausibly outperform the versions evaluated here, particularly on MovieLens-25M, where both already outrank Essence substantially.
- **The domain-dependence mechanism is not fully explained.** "Collaborative/popularity signal strength" is measured post hoc via the baselines' own performance in each domain, not from an independent domain property decided in advance.
- **The Active Cluster Selection ablation is Last.fm-1K only** — not yet verified to generalize to Amazon Books or MovieLens-25M.
- **The adaptive-weighting pilot is unvalidated** — see [above](#7-adaptive-weighting-pilot--exploratory-not-a-result).
